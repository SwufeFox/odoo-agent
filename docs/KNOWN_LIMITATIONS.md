# 已知边界

- 本项目是本地售前 MVP。没有生产上线、客户数据迁移、真实采购、真实消息外发、云资源或付费服务。
- 唯一基线为官方 Odoo 20.0 固定源码提交；不承诺 Odoo18/19 兼容。
- 已接入OpenAI兼容模型，并保留显式本地规则模式。配置、原文来源和最近成功处理方式分别显示；模型拒绝、超时或输出无法核对时保留已有工作，不静默换成规则结果。指定DeepSeek模型已实际跑通模拟连续场景；没有自研API网关、OCR或语音转写能力，不宣称真实客户收益。
- 会议接续只在本次参会人中预填唯一匹配的负责人；姓名末尾显示备注可忽略，同名仍留空待选。明确ISO日期可预填，模糊日期只提示对应行，截止日期允许留空。用户一次采纳才创建/更新任务，不自动确认采购、审批合同或修改权限。
- 当前普通员工没有任何采购/合同读取权限。如需申请人查看无价格进度，应新增明确申请人字段与独立受限接口；不能把原生采购负责人 `user_id` 当申请人。
- 采购审批复用 Odoo20 原生单阈值与经理豁免。自审、金额阶梯、审批催办与拒绝原因向导需要客户确认后另行设计。本次只补必要服务端授权、状态和价格修改守卫。
- 已采纳会议行动项保留不可修改的来源与执行关联；会议可继续追加新事项，另有“确认并锁定会议”结束操作。对原有会议生成任务的负责人、项目等结构保护不变；普通已有任务仅在当前用户有写权限并采纳时更新。
- 员工可准备和提交本人通知提案，负责人生成现有公告草稿后仍须另行发布。公告提供指定员工/全体范围与阅读回执，无邮件或IM推送；回执只表示用户主动点击。
- `mail.thread` 为普通变更记录，不宣称防篡改审计；受信任系统管理员可修改组、代码和数据库。
- 数据库和附件持久化、停止后重启烟测不等同于生产备份恢复。HTTPS、监控、RTO/RPO、异地加密备份仍属于独立生产试点。
- PDF 渲染工具不作为本次业务闭环依赖；合同可保存元数据、正文和原生附件。
- Docker/Compose 是否实际执行，以 `TEST_REPORT.md` 为准；未运行的平台不写成已验证。
- Windows 原生 filestore 垃圾回收可能因文件句柄占用输出 INFO 级 PermissionError；未修改核心或隐藏日志。附件实际内容、数据库记录的重启校验结果见测试报告。
- 报价金额只使用明确数量、币种与税费口径计算，不做未知币种换算；型号或NA相近不等于可替代。产品行与已明确采购税可直接进入原生RFQ草稿，运费保存在准备记录/说明中，不计入RFQ产品行总额。缺少主数据或税项时明确保存为准备记录，不能描述成RFQ已写入。
- 重复整理保留人工改过的字段和补问；重复采纳保留已有关联及原生记录人工修改。后续新报价不会自动改写已生成RFQ的价格或运费，需采购员在原生草稿中决定如何调整。
- 事项简报只复用当前用户可读、显式关联的记录；已完成任务和已转公告准备稿退出待处理卡。没有记录的到货、付款、延期原因不推断成事实。普通列表筛选和导航由代码处理，不使用运行时六代理投票。
