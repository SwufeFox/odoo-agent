# 已知边界

本项目用于本地模拟业务演示。以下限制对应当前代码与 [测试报告](TEST_REPORT.md)，不将未实现或未验证能力列为完成。

## 业务与权限

- 普通员工没有采购和合同读取权限。若需要申请人查看无价格进度，需另行设计申请人字段和受限入口；原生 `purchase.order.user_id` 是采购负责人。
- 采购审批复用Odoo 20原生单阈值与经理豁免。自审、金额阶梯、审批催办和拒绝原因流程尚待确认。
- 报价只按明确的数量、币种、税费口径计算，不做未知币种换算；型号或NA相近不表示可替代。
- 产品行和已明确采购税可写入原生RFQ草稿。运费留在准备记录/说明，不计入RFQ产品行总额；缺少主数据或税项时只能保留准备记录。
- 重复整理保留人工改过的字段和补问；重复采纳保留已有关联和原生记录的人工修改。后续报价不会自动改写既有RFQ价格或运费。
- 会议只在参会人中预填唯一匹配的负责人；同名仍需人工选择。明确ISO日期可预填，模糊日期提示核对，截止日期允许留空。
- 已采纳行动项保留来源与执行关联；会议可以追加新事项，另有“确认并锁定会议”结束操作。更新已有任务须有当前写权限，并由用户采纳。
- 员工仅准备和提交本人通知；负责人转公告草稿后仍须另行发布。阅读回执只表示用户主动点击，无邮件或IM推送。
- 工作台只复用当前用户可读且显式关联的记录。已完成任务和已转公告准备稿退出对应待处理卡；没有记录的到货、付款或延期原因不推断成事实。

完整访问规则见 [角色矩阵](ROLE_MATRIX.md)。系统管理员和数据库管理员是受信任角色；`mail.thread` 只是普通变更记录，不提供防篡改审计承诺。

## 模型与材料

- 支持OpenAI兼容模型及显式本地规则模式；指定DeepSeek模型已用模拟材料验收。配置、原文来源和最近成功方式分别显示，配置成功不代表调用成功。
- 模型拒绝、超时或输出无法核对时，保留已有工作并显示错误，不静默改用规则结果。模型服务可用性取决于所配置的上游。
- AI输出只是可编辑准备内容。正式任务、RFQ和公告仍经服务端校验及人工操作，不由模型自行审批、发布或改变权限。
- 没有自研模型网关、OCR或语音转写；当前输入为文字。真实客户材料的授权与分类尚未确认，不宣称客户实际节省比例。

配置和故障处理见 [运行与配置](RUNNING.md)。

## 运行与交付

- 唯一基线为固定提交的Odoo 20 Community，不承诺Odoo 18/19兼容。已验证平台是Windows源码运行；Docker Compose与Linux路径未实测。
- 数据库和附件的停止、重启验证不等同于生产备份恢复。HTTPS、监控、RTO/RPO和异地加密备份属于独立生产试点范围。
- Windows原生filestore垃圾回收可能因文件句柄占用输出INFO级PermissionError；未修改核心或隐藏日志。实际附件读写与重启校验记录见测试报告。
- PDF渲染工具不是当前闭环依赖，合同可保存元数据、正文和原生附件。
- 未执行生产上线、真实客户迁移、真实采购、邮件/短信/IM外发或云资源创建。生产流程与责任需按 [客户范围确认](CUSTOMER_DISCOVERY.md) 单独确定。
