# 角色与访问矩阵

所有业务数据按当前允许公司隔离。系统管理员是受信任运维账号；不承诺对超级用户、数据库管理员或自行新增权限组提供隔离。

| 对象/操作 | staff | procurement | manager | admin |
|---|---|---|---|---|
| 原生联系人/员工公共目录 | 原生内部用户权限 | 原生采购权限 | 原生管理权限 | 系统配置 |
| RFQ / 采购订单 / 订单行 | 无权 | 原生采购用户 | 原生采购经理 | 受信任配置 |
| 底价 / 供应商报价 | 无权 | 可读 | 可读 | 受信任配置 |
| 报价准备及采用到RFQ草稿 | 无权 | 本公司创建、读取、编辑和采用 | 本公司管理 | 同经理 |
| 合同/正文/附件 | 无权 | 本公司创建、编辑；状态受守卫 | 本公司管理 | 配置角色叠加业务经理 |
| 会议读取 | 自己主持或参与 | 自己主持或参与 | 本公司 | 同经理 |
| 会议修改/整理/采纳/确认 | 主持自己的会议 | 主持自己的会议 | 本公司 | 同经理 |
| 正式任务 | 本人分派/创建且遵守原生规则 | 同 staff | 本公司并遵守原生项目规则 | 同经理 |
| 公告读取 | 本人在接收范围内的已发布公告 | 同 staff | 本公司全部状态 | 同经理 |
| 公告创建/发布/归档 | 无权 | 无权 | 本公司；服务端方法校验 | 同经理 |
| 通知准备与提交 | 本人准备稿，且可读来源会议 | 同 staff | 本公司管理；可转公告草稿 | 同经理 |
| 工作加速/事项简报 | 当前可读任务、会议和通知 | 加入可读报价与采购 | 本公司且遵守原生权限 | 同经理 |
| 阅读回执 | 仅自己的已发布可见公告 | 同 staff | 查看本公司回执 | 同经理 |

采购单 `user_id` 是采购负责人。staff 不拥有采购模型 ACL，也不因会议、任务或公告角色继承采购权限。原生 Purchase Manager 的阈值豁免属于实际原生行为；是否禁止自审等待客户确认。所有演示订单使用虚构数据。

合同、采购单和会议的快捷入口只按当前账号访问，不增加权限。会议“关联任务”的计数与结果仅包含当前用户可读取的原生任务；任务来源链接也遵守会议权限。

公告“已读”和阅读时间只表示当前登录用户的回执；未读筛选按当前用户计算。已读人数和查看该公告全部回执仅负责人可用，员工不能从字段或公开方法获取其他人的阅读情况。

通知准备不赋予员工公告创建或发布权。员工只能编辑自己的准备内容；提交后由负责人生成公告草稿，仍须另行发布。模型返回的责任人、目标任务和接收范围不作为授权依据；服务端按当前账号重新校验。

“员工账号”仅管理员可访问，新建默认普通员工。变更角色继续使用原生安全组；办公首页随办公默认角色更新，已明确选择的其他个人首页保留。
