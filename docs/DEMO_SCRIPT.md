# 演示脚本

仅使用模拟数据。先按 [运行与配置](RUNNING.md) 启动服务并执行 `seed`，从 `.runtime/demo_credentials.json` 取得四个角色的账号；容器凭据位于 `/var/lib/odoo/demo_credentials.json`。角色权限见 [角色矩阵](ROLE_MATRIX.md)。

## 演示前准备

- 连续材料来自 [demo_acceleration.json](../scripts/demo_acceleration.json)，包含两家物镜报价、已有采购任务、接续会议及后续运费补充。
- 默认主页按角色保留；所有角色均可从“显微镜企业办公 → 工作加速”进入自己的工作。
- 先核对“当前配置”和“最近成功来源”。模型模式会实际调用配置的服务；规则模式明确标为本地规则。切换方式见运行文档。
- 材料中的日期为固定模拟日期。需要调整时使用新建演示记录；重复 `seed` 不会清空人工修改或还原业务进度。

## 四幕连续演示

### 1. 报价来了：采购或负责人

1. 打开“报价准备”中的“模拟工作加速：60×物镜采购协调”，点击“整理报价与补问”。
2. 查看比较表：A缺运费；B缺有效期，NA 1.35与目标1.40不同。核对币种、数量、含税口径和缺项，不把未知值当作零。
3. 展开每家报价，查看“原始材料”“可编辑报价”“补问草稿”“匹配与原生询价”。字段依据按需展开，报价和补问可直接修改。
4. 核对A的供应商、产品和采购税，勾选“采用”，返回准备包点击“采用选中行到草稿”，打开真实RFQ检查产品行。

运费保留在准备记录和说明中，不计入RFQ产品行金额。保存补问或采用报价均不向供应商发送消息。

### 2. 开完会：负责人或会议主持人

1. 从准备包的“相关会议”，或“会议与行动项”菜单，打开“模拟接续会议：物镜报价与下次协调”。
2. 点击“整理并接续工作”。核对三类事项：接续已有采购跟进任务、新建研发核对任务、保留“先不下单”决定。
3. 直接调整处理方式、目标任务、责任人、日期和追加进展。明确且唯一的参会人可预填；同名或不确定信息需在对应行核对，截止日期可留空。
4. 勾选要执行的行，点击“采纳选中事项”。打开关联任务，确认旧备注保留、新任务已创建；“仅记录”不会变成下单任务。

重复采纳不重复执行，也不覆盖已采纳后的人工修改。可以继续整理新材料；确实结束纪要时才使用单独的“确认并锁定会议”。

### 3. 安排变了：员工准备，负责人处理

1. 员工在可读会议中点击“准备通知”，检查正文、时间、地点和参会人范围候选。
2. 修改本人准备稿后提交。负责人从“通知准备”打开它，生成未发布的公告草稿。
3. 负责人核对接收范围后另行发布；员工在“内部公告”阅读并点击“确认已读”。负责人可查看该公告回执。
4. 返回“工作加速”，从报价缺项、会议决定、未完成任务等事项卡直接继续工作。

准备、提交、转公告、发布、阅读是不同状态。员工不因准备通知而获得公告发布权，也不会获得报价或合同访问权。

### 4. 运费补充了：采购

1. 在A报价原文末尾追加共享JSON中该报价的 `supplement` 内容，再次整理。
2. 确认运费120元和相关补问更新；之前人工修改的交期/措辞、原生RFQ修改、会议和任务关联仍保留。
3. 重复采用，检查没有新增重复采购行。若需修改已生成RFQ的价格或加入运费，在原生草稿中人工决定。

自动重演使用 `.runtime/venv/Scripts/python.exe scripts/smoke_acceleration.py`。它为每次运行创建独立标识的模拟事项，覆盖连续流程、重复操作和失败后人工继续；运行前提与输出位置见 [运行与配置](RUNNING.md)，实际结果见 [测试报告](TEST_REPORT.md)。

## 规则输入与自然语言输入

本地规则模式使用明确前缀。例如新建会议时可粘贴：

```text
更新任务：跟进精密光学物镜报价与交期 | 负责人：采购小陈 | 截止：2026-11-17 | 进展：补问含税运费。
行动项：整理验收规格 | 负责人：研发小林
仅记录：先不下单，待运费与规格确认。
通知：协调会调整为2026-11-18 10:00，地点二楼会议室。
```

真实模型也接受不带模板前缀的材料。报价示例：

```text
精密光学发来模拟消息：给您报MO60-140油镜，规格是60×、NA 1.40、油浸、M25接口。要2个，每个人民币12,000元含税，税率13%；下单后10天交货，免运费，报价有效至2026年11月30日。
```

会议示例：

```text
采购小陈继续跟进精密光学物镜报价与交期，在2026-11-17前补问含税运费，保留已有任务的备注。
请研发小林新增一项验收规格核对工作，先不填截止日期。规格核对完成前先不下单。
请通知本次参会人员：协调会改到2026-11-18 10:00，在二楼会议室召开。
```

先选择会议参会人员与任务项目，再核对整理结果。相同姓名、缺失事实、型号可替代性都不应靠模型擅自补齐。

## 基础业务与角色交接

### 员工任务

staff 登录默认进入“我的任务”。打开本人任务查看来源会议，使用原生任务状态标记完成；负责人读取同一任务的实际状态。员工无法读取采购单、供应商报价或合同。

### 采购与合同

procurement 登录默认进入询报价与采购单。固定种子包含3家模拟供应商、2张草稿RFQ和1张待审批采购单。

在采购主表打开关联合同，查看编号、责任人、期限和附件；也可从合同“新建询价”，带入供应商、公司和合同后补充物料，再从合同的“采购单”回查。

manager 登录默认进入“待我审批”，可批准科研相机采购单。确认后锁定并记录审批人；采购员不能直接调用方法越权审批或改写已提交价格。Odoo原生采购经理的阈值豁免保留，自审政策见 [客户范围确认](CUSTOMER_DISCOVERY.md)。

### 不依赖AI的会议

manager 新建会议，主公司默认使用“会议任务”项目。手工添加行动项、选择责任人，勾选后“采纳选中事项”，再打开关联任务。截止日期可留空，重复采纳不会重复创建。

在尚未锁定的演示会议中验证无效材料或模型失败：原有行动项应保留，仍能手工新增并采纳。自动化覆盖范围见测试报告。

### 公告与回执

manager 打开公告草稿，指定staff并发布。staff用“未读公告”筛选，点击“确认已读”后查看阅读时间和反馈；manager从“已读人数”查看该公告回执。重复请求只保留一条回执；归档后员工列表不再显示。

### 管理员与新员工

admin 登录默认进入“员工账号”。新建账号默认普通员工，并关联员工目录，不发送邀请邮件。使用原生完整表单，在“Access Rights”中选择办公角色，在“Security”中通过密码向导设置密码；账号进入相应角色首页，个人明确选择的其他首页会保留。

负责人给新员工发布定向公告、分派会议任务；新员工登录后阅读并完成任务；负责人查看结果。基础烟测脚本 `scripts/smoke_test.py` 覆盖这条交接链路。

## 演示后的处理

记录客户最耗时的采购步骤、底价与合同可见范围、会议任务校对责任和公告渠道要求，参照 [客户范围确认](CUSTOMER_DISCOVERY.md) 收集反馈。

重新演示时优先新建记录或运行带独立标识的烟测。完整清空数据会删除模拟记录和附件，仅在确认不再需要后按 [运行与配置](RUNNING.md) 的重置步骤执行。
