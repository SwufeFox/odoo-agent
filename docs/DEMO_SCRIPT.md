# 工作加速连续演示与原有业务路径

仅使用模拟数据。启动并完成 seed 后，从 `.runtime/demo_credentials.json` 取得四个真实本地测试账号。容器方式凭据位于 `/var/lib/odoo/demo_credentials.json`。

## 本轮：同一采购事项的四幕连续演示

共享材料为 `scripts/demo_acceleration.json`，全部供应商、报价、人物和安排均为模拟。引用的外部演示附件未随两份新指令提供，本项目据方案创建了这一组可复用材料。执行 `python scripts/dev.py seed` 后，已有任务、两份报价和接续会议通过固定外部ID关联；重复初始化不覆盖人工进度。

先看“工作加速”的当前配置，以及各产物的最近成功来源。配置真实模型时会实际请求指定服务；失败保留旧工作并显示原因。需要重演纯规则示例时，明确使用 `MOPS_AI_MODE=local`，不要将规则结果记成模型结果。

1. **报价来了。** 采购或负责人进入“报价准备”，打开“模拟工作加速：60×物镜采购协调”，点击“整理报价与补问”。A缺运费，B缺有效期且NA 1.35不同于目标1.40；比较表保留币种与含税口径。打开每行查看分别生成的补问，按需要直接修改。勾选A并“采用选中行到草稿”，回查真实RFQ；运费保留在准备记录，不计入产品行金额。
2. **开完会。** 从准备包“相关会议”或会议菜单进入“模拟接续会议：物镜报价与下次协调”，点击“整理并接续工作”。核对已有采购跟进任务、研发核对建议和“先不下单”记录；若系统找到同名既有任务，会给接续候选，按当前事项核对。可以直接改新增/更新/仅记录、目标、负责人和日期，再一次“采纳选中事项”。只有确实要结束纪要时才另行“确认并锁定会议”。
3. **负责人回来查看。** 打开“工作加速”，查看真实报价缺项、未完成任务与会议决定，直接进入比较/补问或任务。员工可从会议“准备通知”，核对时间地点与参会人候选后提交；负责人在“通知准备”生成未发布公告草稿。准备、生成、发布和阅读四个状态分开。
4. **运费补充了。** 打开A报价行，把共享JSON中A的 `supplement` 追加到原文，再整理。运费120元和相关补问应更新，先前人工修改的交期/措辞、原生RFQ修改及任务关联保留。重复采用不再创建采购行；如需调整既有RFQ价格或加入运费，由采购员在原生草稿决定。

自动重演命令为 `.runtime/venv/Scripts/python.exe scripts/smoke_acceleration.py`；每次使用带运行标识的独立模拟事项，覆盖同一四幕和失败后人工继续。规则模式与真实模型的结果分开记录，以实际输出的处理方式为准。

### 六个开发子代理的独立发现与产物

| 分工 | 三个已落地产物机会 | 保留的下一步机会 |
|---|---|---|
| A 采购 | 多份报价逐项比较；分供应商补问；补充报价到RFQ草稿的接续 | 交期变化后准备关联任务与协调内容 |
| B 会议 | 既有采购任务追加进展；研发任务预填分派；保留不执行决定 | 下一场会议对照未完成事项准备追问清单 |
| C 行政 | 从纪要准备通知；复用参会人范围候选；员工提案交给负责人转公告 | 改期后提出关联任务日期调整建议 |
| D 负责人 | 恢复报价缺口与决定；跟进真实接续任务；识别尚未转稿的通知 | 基于显式关联准备延期协调包 |
| E 集成 | 报价与会议双向入口；当前权限下工作台；复用既有公告发布流程 | 接入原生替代询价比较能力 |
| F 交互 | 直接入口替代重复描述；折叠正常来源、突出疑点；原生表单直接采纳 | 只看本次材料变更及受影响事项的局部视图 |

六个分工真实并行开发，采用文件所有权隔离；主代理统一更新数据库并验证。后续按用户提供的模型配置，报价/会议/通知又分别接入同一OpenAI兼容客户端。开发协作中的多代理不等于每次产品查询都调用六个模型：列表筛选、金额计算、导航和权限判断继续由普通代码完成。

原先需要人工抄报价、找差异、写补问、重录任务和通知；现在需要贴材料、核对例外、一次采纳。仍较烦的步骤是供应商规格是否可替代、复杂表格转成文字，以及未记录事实的人工补齐；这些不伪装成已经自动解决。

以下是原有业务路径，可按需要选演。


## 1. 员工入口（1 分钟）

使用 staff 登录 `http://127.0.0.1:8069`，直接进入“我的任务”。打开本人任务，从“来源会议”查看背景；使用原生任务状态标记完成。打开“内部公告”，用“未读公告”筛选需要阅读的通知。员工不能读取采购单、供应商报价或合同。

## 2. 采购与合同（1–2 分钟）

用 procurement 登录，直接进入询报价与采购单。固定种子有3家模拟供应商、2张草稿RFQ和1张待审批采购单。采购主表直接显示合同；点击“采购合同”回查编号、责任人、期限和附件。在合同中点击“新建询价”，供应商、公司、合同已填入，补充物料后保存。再从合同的“采购单”查看关联订单，无需重复搜索和录入。

用 manager 登录，直接进入“待我审批”。打开科研相机采购单，核对待审批状态并批准；确认后锁定并记录审批人。采购员不能通过直接方法调用批准待审批单，也不能修改已经提交的价格。

原生采购经理可在确认订单时豁免阈值；本次保留实际原生行为，客户自审政策仍待确认。

## 3. 无 AI 的会议闭环（1–2 分钟）

manager 新建会议，使用主公司默认“会议任务”项目。手工添加行动项并选择责任人，截止日期可留空；勾选后点击“采纳选中事项”，直接进入正式任务。会议的“关联任务”可再次打开，重复采纳不会重复创建。staff 只看到有权访问的任务，完成后 manager 看到相同原生任务的实际状态。

## 4. 会议整理与人工恢复

manager 新建会议并粘贴原文，点击“整理并接续工作”。根据当前配置使用真实模型或本地规则，页面显示当前方式、最近成功来源和每行来源。唯一明确的参会人和日期可预填；模糊信息只提示相应行。

核对新增/更新/仅记录、真实目标与负责人后采纳。模型不可用时，既有行动项仍在，可以手工新增并采纳；没有日期的明确任务不被统一阻断。

示例（按实际日期调整）：

```text
待办：确认物镜交期 | 负责人：采购小陈 | 截止：2026-11-20
待办：整理验收规格 | 负责人：研发小林 | 截止：2026-11-18
```

使用一场尚未锁定的会议验证无效输入或模型失败，确认原有行动项未丢失，再手工新增行动项并采纳。异常结构、来源不符及重复采纳也有自动化覆盖；实际模型调用状态以测试报告为准。

## 5. 定向公告（1 分钟）

manager 打开公告草稿，选择 staff 并发布。staff 打开“未读公告”，阅读后点击“确认已读”，看到成功提示、阅读时间；按钮随已读状态隐藏。manager 从公告的“已读人数”直接查看该公告回执。重复请求只保留一条回执，已读状态按用户隔离；归档后员工列表不再显示。

## 6. 权限证据与反馈（30 秒）

查看 `TEST_REPORT.md` 的真实 ORM 访问测试结果。询问客户：采购最耗时步骤、谁能看底价/合同、谁校对会议任务、公告是否需要推送到现有 IM。记录需求，不将演示自动视为生产交付。

## 管理员与新员工交接

使用 admin 登录，直接进入“员工账号”。新建账号默认普通员工、关联员工目录，不发送邀请邮件；完整原生表单的“Access Rights”中可选择员工、采购、负责人或管理员等办公角色。保存后，在“Security”中打开密码向导，点选用户行、输入新密码并保存；原生操作菜单也提供密码操作。新员工登录进入对应角色的入口。

负责人为新员工发布定向公告、在会议中指派一条行动项；新员工确认阅读并完成任务；负责人查看阅读回执和任务完成状态。`smoke_test.py` 使用真实新建账号完整验证这条交接链路。

## 重演与清理

- `python scripts/dev.py seed` 可重复运行：按固定外部 ID 复用记录，保留已经确认的任务/公告，不覆盖人工演示进度。
- 重新演示会议时用“新建”，不要篡改已确认的来源快照。
- 完全重置仅删除本项目自己的模拟数据库与对应 filestore；先停止 Odoo，确认不需要演示数据，再按 README 的显式重置命令操作。不得删除系统既有 PostgreSQL 数据。
