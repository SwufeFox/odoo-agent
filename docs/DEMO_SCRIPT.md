# 5–8 分钟演示脚本

仅使用模拟数据。启动并完成 seed 后，从 `.runtime/demo_credentials.json` 取得四个真实本地测试账号。容器方式凭据位于 `/var/lib/odoo/demo_credentials.json`。

## 1. 员工入口（1 分钟）

使用 staff 登录 `http://127.0.0.1:8069`，直接进入“我的任务”。打开本人任务，从“来源会议”查看背景；使用原生任务状态标记完成。打开“内部公告”，用“未读公告”筛选需要阅读的通知。员工不能读取采购单、供应商报价或合同。

## 2. 采购与合同（1–2 分钟）

用 procurement 登录，直接进入询报价与采购单。固定种子有3家模拟供应商、2张草稿RFQ和1张待审批采购单。采购主表直接显示合同；点击“采购合同”回查编号、责任人、期限和附件。在合同中点击“新建询价”，供应商、公司、合同已填入，补充物料后保存。再从合同的“采购单”查看关联订单，无需重复搜索和录入。

用 manager 登录，直接进入“待我审批”。打开科研相机采购单，核对待审批状态并批准；确认后锁定并记录审批人。采购员不能通过直接方法调用批准待审批单，也不能修改已经提交的价格。

原生采购经理可在确认订单时豁免阈值；本次保留实际原生行为，客户自审政策仍待确认。

## 3. 无 AI 的会议闭环（1–2 分钟）

manager 打开“模拟会议：物镜规格与交期协调”，或新建会议使用主公司默认“会议任务”项目。核对两个手工行动项的责任人和截止日期，勾选采纳，点击“确认并生成任务”，页面直接进入生成的正式任务。会议的“关联任务”可以再次打开，重复确认不会重复创建。staff 登录后只看到有权访问的任务，完成后 manager 看到相同原生任务的实际状态。

## 4. 本地草稿助手（1 分钟）

manager 打开“模拟会议：待办草稿提取演示”，点击“提取待办草稿”。查看建议负责人、建议日期和原文依据。此时没有正式负责人、正式截止日期或任务。

手工选择系统用户、填写正式截止日期并勾选采纳，然后确认生成任务。规则仅识别显式的“待办/行动项”行，不做姓名到用户 ID 的自动映射。

示例（按实际日期调整）：

```text
待办：确认物镜交期 | 负责人：采购小陈 | 截止：2026-11-20
待办：整理验收规格 | 负责人：研发小林 | 截止：2026-11-18
```

将一场新会议的原文改为没有明确行动项的讨论文字，点击提取，查看诊断信息；再手工新增行动项，证明仍可确认分派。异常 Schema 和超时由自动化测试验证，无需向第三方发送任何材料。

## 5. 定向公告（1 分钟）

manager 打开公告草稿，选择 staff 并发布。staff 打开“未读公告”，阅读后点击“确认已读”，看到成功提示、阅读时间；按钮随已读状态隐藏。manager 从公告的“已读人数”直接查看该公告回执。重复请求只保留一条回执，已读状态按用户隔离；归档后员工列表不再显示。

## 6. 权限证据与反馈（30 秒）

查看 `TEST_REPORT.md` 的真实 ORM 访问测试结果。询问客户：采购最耗时步骤、谁能看底价/合同、谁校对会议任务、公告是否需要推送到现有 IM。记录需求，不将演示自动视为生产交付。

## 管理员与新员工交接

使用 admin 登录，直接进入“员工账号”。新建账号默认普通员工、关联员工目录，不发送邀请邮件；完整原生表单的“Access Rights”中可选择员工、采购、负责人或管理员等办公角色。保存后，在“Security”中打开密码向导，点选用户行、输入新密码并保存；原生操作菜单也提供密码操作。新员工登录进入对应角色的入口。

负责人为新员工发布定向公告、在会议中指派一条行动项；新员工确认阅读并完成任务；负责人查看阅读回执和任务完成状态。`smoke_test.py` 使用真实新建账号完整验证这条交接链路。

## 重演与清理

- `python scripts/dev.py seed` 可重复运行：按固定外部 ID 复用记录，保留已经确认的任务/公告，不覆盖人工演示进度。
- 重新演示会议时用“新建”，不要篡改已确认的来源快照。
- 完全重置仅删除本项目自己的模拟数据库与对应 filestore；先停止 Odoo，确认不需要演示数据，再按 README 的显式重置命令操作。不得删除系统既有 PostgreSQL 数据。
