# 功能适配与差距

本表描述当前实现。运行方式见 [运行与配置](RUNNING.md)，角色边界见 [角色矩阵](ROLE_MATRIX.md)，已执行验证见 [测试报告](TEST_REPORT.md)。

## 当前能力

| 需求 | 实现方式 | 当前边界 |
|---|---|---|
| 供应商、物料、RFQ、采购订单 | 原生 Contacts / Purchase | 模拟供应商与订单，不对外发送 |
| 报价准备与补问 | `mops.quote.pack` / `mops.quote.line` + 原生 Purchase | 多供应商缺项/规格比较、分别补问、采纳到RFQ草稿；保留人工修改和已有采购关联 |
| 合同台账 | `mops.contract` | 编号、主体、责任人、期限、状态、正文与附件；一合同多订单 |
| 账号与员工目录 | 原生 Users / HR | staff、procurement、manager、admin四角色；不含薪酬/考勤 |
| 底价与合同保密 | ACL、记录规则、字段权限及服务端校验 | 员工不能读取采购、订单行、合同或供应商报价 |
| 采购审批 | 原生 Odoo 20 路径加方法守卫 | 单阈值及经理豁免；不新建审批引擎 |
| 会议纪要 | `mops.meeting` | 主持人、参会人、文本、状态和公司隔离 |
| 行动项与任务 | 准备模型 + 原生 Project | 明确候选可预填；采纳后新增、更新或仅记录；日期可空，重复采纳幂等 |
| 公告 | `mops.notice` | 草稿、发布、归档、指定员工或全体范围；员工不可发布 |
| 公告回执 | `mops.notice.read` | 本人确认、唯一回执，不能伪造他人阅读 |
| 员工通知准备 | `mops.notice.proposal` + 既有公告 | 本人准备并提交，负责人转为未发布草稿 |
| 工作加速与事项简报 | 权限内跨记录入口 | 复用报价缺项、任务、会议决定和通知状态；不推断未记录事实 |
| AI整理 | 统一OpenAI兼容客户端和领域适配器 | 真实模型及显式规则模式；Schema、原文依据、权限重验，失败保留已有工作 |

## 开发分工与后续候选

六个开发分工的落地产物与保留机会如下。右列是候选方向，不属于当前已实现或已承诺范围。

| 分工 | 已落地产物 | 后续候选 |
|---|---|---|
| A 采购 | 多份报价逐项比较；分供应商补问；补充报价到RFQ草稿的接续 | 交期变化后准备关联任务与协调内容 |
| B 会议 | 既有采购任务追加进展；研发任务预填分派；保留不执行决定 | 下一场会议对照未完成事项准备追问清单 |
| C 行政 | 从纪要准备通知；复用参会人候选；员工提案交给负责人转公告 | 改期后提出关联任务日期调整建议 |
| D 负责人 | 恢复报价缺口与决定；跟进真实接续任务；识别尚未转稿的通知 | 基于显式关联准备延期协调包 |
| E 集成 | 报价与会议双向入口；权限内工作台；复用既有公告发布流程 | 接入原生替代询价比较能力 |
| F 交互 | 直接入口；折叠来源、突出疑点；在业务表单中采纳 | 只看本次材料变更及受影响事项的局部视图 |

开发阶段的六个分工并行工作；运行时的报价、会议和通知共用一个模型客户端。列表筛选、导航、金额计算和权限判断由普通代码处理，不进行六模型投票。
