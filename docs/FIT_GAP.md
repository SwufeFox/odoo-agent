# 功能适配与差距

| 需求 | 方式 | 本次边界 |
|---|---|---|
| 供应商、物料、RFQ、采购订单 | 原生 Contacts / Purchase | 3 家模拟供应商、2 张 RFQ、1 张原生确认/审批订单；不对外发送 |
| 合同台账 | 定制 `mops.contract` | 编号、标题、合同方、责任人、期限、状态、正文、合法附件；一合同多订单 |
| 账号与员工目录 | 原生 Users / HR | staff、procurement、manager、admin 四角色；无薪酬/考勤 |
| 底价与合同保密 | ACL、记录规则、字段权限、服务端校验 | 普通员工不得读采购、订单行、合同、供应商报价；不可只隐藏菜单 |
| 采购审批 | 复用实际 Odoo 20 原生路径 | 先检查源码，再实施必要的方法守卫；不新建审批引擎，不假定自审政策 |
| 会议纪要 | 定制 `mops.meeting` | 主持人、时间、参与者、文本、状态和公司隔离 |
| 行动项与任务 | 草稿模型 + 原生 Project | 人工确认责任人/截止日期后生成；重复确认幂等；无第二份任务状态 |
| 公告 | 定制 `mops.notice` | 草稿、发布、归档、指定接收人/全体员工；服务端阻止员工发布 |
| 公告阅读回执 | 定制 `mops.notice.read` | 自己确认阅读，唯一回执，不能伪造他人 |
| Agent 提取 | add-on 内规则适配器 | 严格 Schema、字段/数量/长度约束、失败可手工继续；只生成待确认草稿 |
| 外部 LLM、IM、邮件、语音、OCR | 暂不开发 | 没有外部数据通信或付费依赖 |
| 多级审批、会计、库存、签章、付款 | 暂不开发 | 等客户确认真实流程后单独立项 |
| 生产运维 | 暂不开发 | 不把本地重启持久化验证表述为生产备份恢复 |
