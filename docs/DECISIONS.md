# 实现决策

## ADR-001：唯一测试基线 Odoo 20 Community

用户明确要求 Odoo 20。以官方 20.0 源码固定提交构建，不声明其他主版本兼容。PostgreSQL 17 用于本机和 Compose；部署凭据由本地初始化生成。

## ADR-002：单一 add-on

`microscope_office_mvp` 依赖 Contacts、Purchase、Project、HR、Mail。Odoo ORM 是唯一业务事实来源；无需独立 FastAPI 服务、第二份业务数据库或共享管理员 API Key。

## ADR-003：保密边界

普通员工不授予采购或合同模型访问权，因此不能通过采购表、订单行、供应商报价读取底价。采购/负责人使用原生采购权限；会议限主持人、参与者及负责人；公告限目标员工且仅发布后可见。按公司隔离记录。任务复用 `project.task`，增加会议任务访问约束以补足原生项目权限。

ASSUMPTION：员工首期不需要查看采购申请进度，因此不为其开放删减价格的采购视图。`purchase.order.user_id` 保持原生采购负责人语义。

## ADR-004：人工确认与幂等

会议草稿含候选姓名/日期；规则适配器不填正式责任人、正式截止日期，也不生成任务。主持人或负责人校对后确认；事务锁与任务关联保证重复确认不重复派发。未知人员不得通过模型输出映射为系统权限。

## ADR-005：本地演示边界

只监听 loopback，PostgreSQL 不发布容器端口。禁用外发邮件；演示账号密码仅保存到忽略目录。人工业务路径不依赖 AI。规则适配器清楚标为本地规则演示，不声称已接入真实大模型。

## 尚待客户确认

真实审批与自审政策、部门与跨公司边界、合同主体和关联基数、公告接收范围、模型授权与数据分类。售前环境不承诺生产 SLA、备份恢复或合规认证。
